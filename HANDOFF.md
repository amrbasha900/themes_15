### Session 10b — smart widgets, workspace actions, comparisons (2026-09-16)

**Smart widgets** — a new DocType **Themate Widget** (`themate/themate/doctype/themate_widget`),
computed live by `themate/widgets.py` from ANY DocType through `frappe.get_list` (so the user's
permissions apply; a user without read gets `error: no_permission`, never data; results are cached
60 s per user, widget and language). Eleven types: KPI, Goal, Rate, Trend, Leaderboard, Breakdown,
Funnel, Watchlist, Upcoming, Recent, Aging — the docstring at the top of `widgets.py` is the
reference. Periods: Today / This Week / This Month / This Quarter / This Year / Last 7·30·90 Days /
Custom Range (from_date, to_date) / All Time. Comparison (`compare_with`): Previous Period (a whole
month vs. the whole previous month, a year vs. the year before, a range vs. the same length before
it), Same Period Last Year (whole months stay whole; Feb 2024 → Feb 2023), or None. Pinned in
`tests/widgets.test.py` (29 checks, bench python).

Client: `public/js/widgets/smart_widget.js` registers `frappe.widget.widget_factory.tm_widget`
(extends Frappe's Widget base, obtained as the prototype of the number-card widget); values go
through Frappe's own formatters with `{inline: true}` and are wrapped in `<bdi>` — an Arabic
currency symbol next to "/" or "vs" otherwise reorders the line. Every card links to the filtered
list / form. Styling in `components/_smart-widgets.scss` (tone = widget Colour via
`--tm-sw-fg/bg`; good/bad always the semantic success/danger tokens).

Editor block: `public/js/workspace/smart_block.js` adds the `tm_widget` tool (data
`{tm_widget_name, col}`) to editor.js. Frappe hard-codes the tool list and keeps the EditorJS
class as a module import, so `initialize_editorjs` is wrapped: Frappe builds `this.tools` and its
editor into a hidden throwaway `#editorjs` (the real holder is renamed for the moment — EditorJS
resolves a string holder twice, at validate() and at mount), the class is taken from that
instance, the throwaway is destroyed, and the real editor is created on the real element with the
same tools plus ours. Content stays plain workspace JSON — `save_page` keeps unknown block types
and `clean_up` only prunes the known ones (desk/desktop.py). The "+" menu shows **Smart Widget**;
its dialog picks a Themate Widget; the widget's edit button lets you swap it or open its settings.

Form (`themate_widget.js`): field pickers list the DocType's own fields typed for the job; Filters
(and, for Rate, Numerator Filters) use FilterGroup in a dialog exactly like Number Card; a live
preview renders the real card; **Add to Workspace** appends the block through
`themate.widgets.add_to_workspace` (own private workspaces, public ones for Workspace Managers).
`themate/widget_samples.py` seeds 19 ready-made widgets on ERPNext sites in `after_migrate`

**List performance, report column freezing, board polish (2026-09-18, Session 14).**

**The freeze on long lists was Frappe's, and it is measurable.** `base_list.js:644`
appends every row in one synchronous loop. Measured on this bench with 866 DocType rows
(33k nodes), stock Frappe produces **one 562 ms long task and one 176 ms long task — 738 ms
of tab that answers no click and no scroll**, and it grows linearly (2500 rows ≈ 2 s).
Two changes, both in the list the theme already owns:

- `list_pager.js` now renders in chunks of 60 rows, one per animation frame, with the first
  chunk synchronous so nothing appears slower than before. `set_rows_as_checked()` and
  `toggle_result_area()` are re-run after the last chunk, because `render()` calls them
  before the rows exist. An in-flight chunk run is cancelled if a refresh lands mid-stream.
  Row menus are added per chunk (`addRowMenus` is idempotent).
- `_list.scss` gives `.list-row-container` `content-visibility: auto` with
  `contain-intrinsic-size: auto var(--tm-row-h)`, so the browser lays out and paints only the
  rows near the viewport. Render + forced recalc: **783 ms → 529 ms** on its own.

Together: **738 ms of blocking → a single 71 ms task**, with 866 rows and 866 row menus, and
select-all still checks all 866. Report View needed nothing — frappe-datatable virtualises
with HyperList (866 records, 53 rows in the DOM, 123 ms), which the numbers confirmed before
anything was changed there.

Two things that looked like the cause and were not, recorded so nobody re-derives them:
the `:has()` rules cost ~80 ms of the 950 ms, not the bulk; and batching the 866 `.append()`
calls into one string or one DocumentFragment is *slower*, not faster (576 / 647 / 663 ms) —
the cost is the browser's layout for 33k nodes, not jQuery's parse.

**Report View: freeze columns** (`js/core/report_columns.js`, `_datatable.scss`). Two entries
on the column dropdown — *Freeze up to this column* / *Unfreeze columns* — persisted per
doctype in `localStorage["tm-report-freeze"]`. Two library facts decide the implementation:
`.dt-scrollable` scrolls natively, so body cells pin with plain `position: sticky`; but
`.dt-header` does **not** scroll — `style.js:51` mirrors it with
`transform: translateX(-scrollLeft)` — so the frozen header cells get the opposite translate
from a `--tm-dt-x` custom property this file keeps in step. Offsets are read from the rendered
header (a resized column moves everything after it, so a ResizeObserver recomputes) and written
into a `<style>` element, never inline, because the body is virtualised and inline styles on a
cell are thrown away on the next scroll. Note `datatable.wrapper` is the element Frappe handed
the library; `datatable.datatableWrapper` is `.datatable` itself, and that is what the rules
are scoped to.

**Dashboard View is hidden from the view switcher** — `li[data-view="Dashboard"]` in
`_list.scss`. `list_view_select.js:145` tags each entry with `data-view`, and offers Dashboard
for every doctype whether or not one exists. Hidden, not unregistered, so the URL still
resolves and the master kill-switch brings it back.

## Two bugs that were mine, both fixed

**1. The master switch disabled the theme on every existing site.**
`enable_theme` was read with `... if settings.get("enable_theme") is not None
else 1`. That guard can never fire: `BaseDocument._fix_numeric_types`
(`frappe/model/base_document.py:723`) runs `cint()` over every Check field when a
Single loads, so an unset Check reads back as `0`, never `None`. The new field
had no row in `tabSingles`, resolved to `0`, and `data-tm-enabled="off"` stripped
all 713 rules including the Frappe variable bridge. Flags now read
`frappe.db.get_single_value`, where NULL still means NULL, and `after_migrate`
writes explicit values. Guarded by `tests/flags.test.py`, which was verified to
fail against the old code with the exact reported symptom.

**2. `package.json` sat at the app root.** Frappe's esbuild runs `yarn build`
inside any app whose root `package.json` declares a `build` script
(`frappe/esbuild/esbuild.js:447`). It didn't declare one, so nothing broke — but
a later `build` script would have broken `bench build` for every app on the
bench, and its presence invites `yarn install` to pull Playwright onto a
production bench. Moved to `tests/`.

## Architecture in four lines

- `scss/tokens/` — palette, semantic, bridge, dark, guard. Raw colours only in
  `_palette.scss` and `_dark.scss`.
- `tokens/_bridge.scss` maps verified native Frappe variables onto tokens. Dark
  redefines tokens only; the bridge is mode-independent and re-resolves itself.
- Theme state is Frappe's: `data-theme-mode` + `data-theme` via
  `frappe.ui.set_theme()`. No parallel attribute.
- `data-tm-enabled="off"` is a real rollback (tokens + bridge + all rules). The
  per-area flags remove structure only — Frappe defines its palette globally on
  `:root`, so per-area colour rollback is not implementable.

## Setup wizard, grid lag, dashboards off the workspace (2026-10-27)

- **Setup wizard**: `msidebar_override.js` mounts nothing while
  `boot.sysdefaults.setup_complete` is false and sets `html[data-tm-setup=pending]`,

- **Child-table lag**: `body:has(.modern-sidebar.collapsed) .main-section` made
  Chrome re-check a `:has()` on body for every DOM change; adding row 15 to a

  (`getPropertyValue` under Frappe's grid `refresh_field` → jQuery `.show()`),
  then delta-debugging the bundle's top-level CSS rules with Playwright. Never
  put `:has()` on `body`/`html`; use a class (`body.sidebar-collapsed`).
- **Dashboards**: workspaces no longer split into Dashboard | Records or show
  module dashboards in place — every block renders as Frappe lays it out. A

  On" and `themate.api.get_workspace_dashboards`.
